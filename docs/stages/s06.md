# S6 — Transações, locks e deadlocks

- **Suite:** `tests/p_06.spec.ts` · **Tag:** `s06` · **Status:** pendente

## O que implementar no motor

- **Service:** `jobs.service.ts` — métodos que demonstram `FOR UPDATE`,
  `FOR UPDATE SKIP LOCKED` e `pg_try_advisory_lock` (tarefa singleton).
- **Sem controller** — é a base do claim do S7.
- **Para:** N réplicas concorrerem sem duplicar trabalho e eleger líder.

## Queries possíveis

```sql
SELECT * FROM job WHERE id = $1 FOR UPDATE;

SELECT * FROM job WHERE status = 'pending' ORDER BY run_at LIMIT 1
FOR UPDATE SKIP LOCKED;

SELECT pg_try_advisory_lock(42);
```

## Baseline × meta

| Item | Baseline | Meta |
|---|---|---|
| `FOR UPDATE` concorrente | bloqueia/espera | espera controlada |
| `SKIP LOCKED` | — | não espera |
| advisory lock | — | single-runner |

## Critério de aceite

`SKIP LOCKED` não bloqueia; contenção em `pg_locks`; deadlock detectado.
