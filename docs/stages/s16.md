# S16 — Profiling e load testing

- **Suite de testes:** `tests/p_16.spec.ts`
- **Tag:** `s16`
- **Status:** pendente

## Objetivo

Transformar "acho que melhorou" em **número**: medir antes/depois de cada
incremento e olhar a cauda (p95/p99), não a média.

## Incremento

- `scripts/bench.ts` rodando o mesmo cenário nas tags `s02`, `s07`, `s11`.
- `autocannon`/`k6` para carga; `clinic doctor/flame` para CPU.
- `EXPLAIN (ANALYZE)` sob carga.

## Queries prováveis

As queries medidas são as do motor (claim, listagem, histórico):

```sql
-- claim sob carga
EXPLAIN (ANALYZE, BUFFERS) SELECT id FROM job
WHERE status = 'pending' AND run_at <= now()
ORDER BY run_at LIMIT 10 FOR UPDATE SKIP LOCKED;

-- por pipeline
EXPLAIN (ANALYZE, BUFFERS) SELECT * FROM job WHERE pipeline_id = $1;

-- histórico
EXPLAIN (ANALYZE, BUFFERS) SELECT * FROM execution WHERE job_id = $1;
```

## O que a suite `p_16` deve validar

- O bench roda o mesmo cenário de forma reproduzível (mesmo volume/query).
- Há medição antes/depois por etapa (tags `s02`, `s07`, `s11`).
- p99 cai (não só a média).
- A fila não acumula durante o teste.

## O que observar

- Latências p50/p95/p99 (k6/autocannon) e throughput.
- `EXPLAIN (ANALYZE, BUFFERS)` sob carga (planos mudam com cache/concorrência).
- `clinic flame` para gargalo de CPU; separar I/O de CPU.
