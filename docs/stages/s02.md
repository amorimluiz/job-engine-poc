# S2 — Índices + EXPLAIN

- **Suite:** `tests/p_02.spec.ts` · **Tag:** `s02` · **Status:** pendente

## O que implementar no motor

- **Controller:** `jobs.controller.ts` — endpoints de leitura:
  `GET /jobs?pipeline_id=...` e `GET /jobs/:id/executions`.
- **Service:** `jobs.service.ts` — `listByPipeline(pipelineId)`,
  `listPending(limit)` (a fatia que o claim do S7 vai usar) e
  `listExecutions(jobId)`.
- **Para:** servir as leituras do motor e preparar a seleção do claim.
- **DB:** criar os índices que estas queries usam e habilitar
  `pg_stat_statements` (o planner ainda pode preferir Seq Scan em alguns casos).

## Queries possíveis

```sql
SELECT * FROM job WHERE pipeline_id = $1;

SELECT * FROM job WHERE pipeline_id = $1 AND status = 'pending';

SELECT * FROM job WHERE status = 'pending' AND run_at <= now()
ORDER BY run_at LIMIT 10;

SELECT * FROM execution WHERE job_id = $1 ORDER BY started_at DESC;
```

## Baseline × meta

| Query | Sem índice (medido) | Meta pós-otimização |
|---|---|---|
| `job WHERE pipeline_id` | ~23 ms | < 1 ms |
| `job WHERE pipeline_id AND status` | ~23 ms | < 1 ms |
| claim `status, run_at LIMIT 10` | ~59 ms | < 1 ms |
| `execution WHERE job_id` | 0,04 ms (vazio) | < 1 ms (cheio) |

## Critério de aceite

Seq Scan → Index Scan / Index Only / Bitmap e queda de `total_exec_time`.
