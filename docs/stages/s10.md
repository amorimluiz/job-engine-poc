## Objetivo

Desacoplar quem produz de quem processa: publicar jobs prontos numa fila e
consumir, sobrevivendo a restart do broker.

## Incremento

- Publicar jobs prontos numa fila `jobs` (exchange/queue/binding).
- Mensagem **persistente** + fila **durable**.
- Derrubar o broker no meio e ver o que perde/segura.

## Queries prováveis

Nenhuma SQL de domínio. O foco é AMQP:

```ts
// producer
await channel.assertQueue('jobs', { durable: true });
channel.sendToQueue('jobs', Buffer.from(JSON.stringify(payload)), {
  persistent: true,
});

// consumer
await channel.assertQueue('jobs', { durable: true });
channel.consume('jobs', (msg) => { /* ... */ });
```

```sql
-- opcional: registrar a intenção no outbox do banco (liga com S14)
INSERT INTO outbox(job_id, payload) VALUES ($1, $2);
```

## O que a suite `p_10` deve validar

- Mensagem **persistente** sobrevive a restart do broker.
- Fila **durable** sobrevive a restart.
- Entender o que se perde: publicação sem confirmação pode sumir (liga com S13).

## O que observar

- RabbitMQ Management UI: `messages`, `messages_ready`, `messages_unacknowledged`.
- Diferença entre "publiquei" e "foi entregue" (confirm channel no S13).
