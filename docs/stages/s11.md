# S11 — Prefetch/QoS, ack/nack e redelivery

- **Suite de testes:** `tests/p_11.spec.ts`
- **Tag:** `s11`
- **Status:** pendente

## Objetivo

Backpressure de verdade no consumidor: sem isso, o broker empurra tudo e a
memória/unacked explodem sob carga.

## Incremento

- Consumir **sem prefetch** (medir memória/unacked) e depois com `prefetch(10)`.
- `noAck:false` + `ack`/`nack(requeue)`.

## Queries prováveis

Foco AMQP; nada de SQL de domínio. O efeito no banco aparece no outbox/status:

```ts
// backpressure: limita quantas mensagens não confirmadas por canal
await channel.prefetch(10);

await channel.assertQueue('jobs', { durable: true });
channel.consume('jobs', async (msg) => {
  if (!msg) return;
  try {
    await process(JSON.parse(msg.content.toString()));
    channel.ack(msg);
  } catch {
    channel.nack(msg, false, true); // devolve para a fila
  }
}, { noAck: false });
```

## O que a suite `p_11` deve validar

- Sem prefetch, `messages_unacknowledged` e memória sobem sem limite.
- Com `prefetch(10)`, o consumo fica **estável** e limitado.
- `ack` remove a mensagem; `nack(requeue)` a devolve.

## O que observar

- Management UI: `messages_unacknowledged` por canal.
- Memória do processo do consumidor (RSS/heap) sob carga.
- Sem prefetch, o consumer pode morrer e perder mensagens em voo.
