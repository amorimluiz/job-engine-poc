# S0 — Setup do ambiente

- **Suite de testes:** `tests/p_00.spec.ts`
- **Tag:** `s00`
- **Status:** concluído

## Objetivo

Banco, broker e app de pé, com volume disponível para revelar gargalos. É a base
de medição de todas as etapas.

## Incremento

`docker-compose.yml` (postgres:16 + rabbitmq:3-management + pgbouncer comentado),
projeto Node/TypeScript strict com Express, `DataSource` do TypeORM, `/health` e
`seed.ts`/`bench.ts` (placeholders nesta etapa).

## Queries prováveis

```sql
-- health check da app (SELECT 1 no Postgres)
SELECT 1;

-- verificação de volume (placeholder no S0; passa a valer no S1)
SELECT count(*) FROM job;
```

## O que a suite `p_00` valida

- Postgres responde a `SELECT 1`.
- RabbitMQ aceita conexão TCP na porta 5672.
- `GET /health` responde 200 (pulado se a app não estiver no ar).

## O que observar no banco

Nenhuma tabela de domínio ainda. O foco é garantir a infraestrutura saudável —
em especial que o `shared_preload_libraries` do `pg_stat_statements` possa ser
habilitado no S2.
