# S15 — Observabilidade

- **Suite de testes:** `tests/p_15.spec.ts`
- **Tag:** `s15`
- **Status:** pendente

## Objetivo

Enxergar a fila acumular e drenar. Sem métricas de profundidade e de **idade do
item mais antigo**, o motor falha em silêncio.

## Incremento

- `/metrics` (prom-client) com `jobs_processed_total`, `job_duration_seconds`
  (histograma), `outbox_pending`, `outbox_oldest_age_seconds`.
- `pg_stat_statements` como painel de queries.

## Queries prováveis

```sql
-- profundidade da fila por status
SELECT status, count(*) FROM job GROUP BY status;

-- idade do item mais antigo pendente (leading indicator)
SELECT extract(epoch FROM now() - min(run_at)) AS oldest_age_seconds
FROM job WHERE status = 'pending';

-- lag do outbox
SELECT count(*) AS pending,
       extract(epoch FROM now() - min(created_at)) AS oldest_age_seconds
FROM outbox WHERE sent_at IS NULL;

-- top queries por tempo acumulado
SELECT query, calls, total_exec_time, mean_exec_time
FROM pg_stat_statements ORDER BY total_exec_time DESC LIMIT 10;
```

## O que a suite `p_15` deve validar

- `GET /metrics` expõe os gauges/counters acima.
- A profundidade da fila cai quando o motor drena (não acumula).
- A idade do mais antigo é exposta e não cresce indefinidamente.

## O que observar no banco

- `pg_stat_statements` (`total_exec_time` vs `mean_exec_time`) para achar a
  query que mais custa no total.
- Diferença entre **profundidade** (quantos) e **idade** (há quanto tempo) — a
  idade é o que denuncia consumidor travado.
