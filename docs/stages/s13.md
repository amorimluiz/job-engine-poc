# S13 — Publisher confirms, quorum e consumidor idempotente

- **Suite de testes:** `tests/p_13.spec.ts`
- **Tag:** `s13`
- **Status:** pendente

## Objetivo

Garantir que **"publiquei" = "chegou"** (confirms) e que reentrega **não duplica
efeito** (consumidor idempotente). At-least-once implica que duplicata vai
acontecer.

## Incremento

- `confirm channel` + `waitForConfirms`.
- Tabela `processed(execution_id unique)` com consumidor que ignora duplicata.
- Reentregar a mesma mensagem de propósito.

## Queries prováveis

```sql
-- dedup: registra o processamento só uma vez
INSERT INTO processed (execution_id)
VALUES ($1)
ON CONFLICT (execution_id) DO NOTHING
RETURNING execution_id;

-- se RETURNING vier vazio, é duplicata -> ignorar
-- (alternativa: SELECT antes)
SELECT 1 FROM processed WHERE execution_id = $1;
```

```ts
// confirmação de publicação
const ch = await conn.createConfirmChannel();
ch.publish('', 'jobs', body, { persistent: true });
await ch.waitForConfirms();
```

## O que a suite `p_13` deve validar

- `waitForConfirms` resolve antes de considerar publicado.
- A **segunda entrega** da mesma mensagem é descartada sem efeito (linha única
  em `processed`).
- O efeito colateral (ex.: uma execution) ocorre **uma única vez**.

## O que observar no banco

- `processed(execution_id unique)` — a unicidade é o que garante a dedup.
- Contagem de `execution` por job: deve ser 1 mesmo com reentrega.
